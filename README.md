# Учебная доска

Интерактивная бесконечная доска для совместных занятий учителя и учеников по математике и физике: школьный курс (5–11 классы, ОГЭ/ЕГЭ, олимпиады) и университетский. Интерфейс на русском языке, работает в браузере на компьютере, планшете и интерактивной панели.

## Возможности

- **Доска:** бесконечный холст со страницами, перо и маркер с распознаванием фигур, фигуры, текст с форматированием и таблицами, формулы (редактор, калькулятор с единицами, распознавание рукописных формул), картинки и PDF, группы, слои, блокировка, отмена, поиск команд Ctrl+K.
- **Совместная работа:** все участники видят изменения и курсоры сразу; работа без сети с досинхронизацией; режимы урока (лекция, совместная работа, «мел» отдельным ученикам), показ доски учителя, лазерная указка, «поднять руку».
- **Задания:** раздача копий доски классу или ученикам, сдача, проверка с пометками и отметкой, возврат на доработку.
- **Математика:** планиметрия с построениями, линейкой и циркулем; стереометрия (3D-сцена, сечения, развёртки); графики и анализ; аналитическая геометрия; линейная алгебра; функции нескольких переменных и векторный анализ; дифференциальные уравнения; комплексные числа; вероятность и статистика; дискретная математика.
- **Физика:** векторы и силы, «Дано / СИ / Решение»; механика с анимациями; электростатика и цепи постоянного тока; магнетизм и индукция; колебания и волны; современная физика (теория относительности, кванты, атом и ядро).
- **Библиотека шаблонов** (встроенные доски-задачи и свои, общий доступ) и **справочник формул**.
- **Экспорт** PNG, SVG, PDF и **история версий** с восстановлением.
- **Администрирование:** пользователи (в том числе импорт CSV), классы, журнал действий.

Подробнее о разделах и API — [docs/USAGE.md](docs/USAGE.md).

## Установка на сервер

Всё работает в Docker на одном сервере: база PostgreSQL, сервер приложения, Nginx с сайтом и HTTPS.

**Требования:** Linux (проверялось на Ubuntu 24.04), 2 ядра, 4 ГБ памяти (+3 ГБ для распознавания рукописных формул), 20 ГБ на диске; [Docker Engine с Compose](https://docs.docker.com/engine/install/ubuntu/); для HTTPS — доменное имя, указывающее на сервер, и открытые порты 80 и 443.

```bash
git clone https://github.com/masahaka229/doska.git
cd doska
git checkout stage-1-architecture

# с доменом — сразу HTTPS (сертификат Let's Encrypt выпускается и продлевается сам)
./deploy/scripts/install.sh --domain doska.school.ru --email it@school.ru

# или в локальной сети по IP (без домена, по HTTP)
./deploy/scripts/install.sh --ip 192.168.1.10
```

Без ключей скрипт задаст вопросы. Он создаст `.env` со случайными паролями (доступ только владельцу), соберёт образы (первый раз — 5–15 минут), запустит сайт и напечатает логин и пароль администратора. При первом входе пароль нужно сменить. Дальше в панели администратора создайте учителей и учеников — по одному или импортом CSV.

Ещё ключи `install.sh`: `--admin-login`, `--admin-password`, `--http-port`, `--https-port`, `--ocr` (распознавание формул), `--no-build`, `--force`; справка — `--help`.

Без скрипта: `cp .env.example .env`, заполнить по комментариям в файле, затем `docker compose up -d --build` и при домене `./deploy/scripts/https.sh`.

### Автозапуск и ежедневная копия

```bash
sudo ./deploy/scripts/systemd.sh            # служба doska + таймер копии в 03:30
BACKUP_TIME=02:15 sudo ./deploy/scripts/systemd.sh
sudo ./deploy/scripts/systemd.sh --remove
```

Контейнеры и без этого перезапускаются после сбоя и перезагрузки (`restart: unless-stopped`).

### HTTPS позже

Если сначала ставили по IP, а потом появился домен: в `.env` задайте `DOMAIN`, `LETSENCRYPT_EMAIL`, `PUBLIC_ORIGIN=https://домен`, `COOKIE_SECURE=true`, добавьте `tls` в `COMPOSE_PROFILES` и выполните:

```bash
./deploy/scripts/https.sh
docker compose up -d
```

Nginx сам переключается на HTTPS, когда появляется сертификат, и раз в 6 часов перечитывает его после продления.

### Рядом с другим сайтом на том же сервере

Если порты 80 и 443 уже заняты другим сайтом со своим прокси (Caddy, Nginx), доска ставится на внутренний порт, а HTTPS для неё делает этот прокси:

```bash
./deploy/scripts/install.sh --behind-proxy https://doska.example.ru --local-port 8080
```

Сайт слушает только `127.0.0.1:8080` (и `8081`), снаружи недоступен. В конфигурацию прокси добавьте отдельный адрес (поддомен), например в `Caddyfile`:

```
doska.example.ru {
	reverse_proxy 127.0.0.1:8080
}
```

WebSocket Caddy пропускает сам; для Nginx нужны `proxy_http_version 1.1` и заголовки `Upgrade`/`Connection` для `/ws`. Без своего домена подойдёт `doska.1-2-3-4.sslip.io` (IP сервера через дефисы). Проверено с Caddy 2 в сети хоста.

## Обслуживание

| Задача | Команда |
|---|---|
| Обновить до новой версии | `./deploy/scripts/update.sh` — копия, `git pull`, сборка, перезапуск (миграции базы — сами при запуске) |
| Резервная копия | `./deploy/scripts/backup.sh` — база, файлы и `.env` в `backups/<дата>`; хранятся 14 последних (`KEEP=30` — больше) |
| Восстановить | `./deploy/scripts/restore.sh backups/<дата>` — перед этим сохраняется копия текущего состояния |
| Состояние | `docker compose ps` |
| Журналы | `docker compose logs -f backend` (журналы контейнеров ограничены: 5 файлов по 10 МБ) |
| Остановить / запустить | `docker compose stop` / `docker compose up -d` |

**Перенос на другой сервер:** скопируйте каталог копии на новый сервер, склонируйте проект, положите `env` из копии в `.env` (при смене адреса поправьте `PUBLIC_ORIGIN` и `DOMAIN`), выполните `docker compose up -d --build`, затем `./deploy/scripts/restore.sh --yes <каталог>`.

**Копия содержит секреты** (пароли базы, ключ подписи сессий): храните её как пароли и не выкладывайте в общий доступ. Копии на том же диске не спасут от поломки диска — копируйте `backups/` на другой компьютер или в облако.

### Распознавание рукописных формул

Необязательный сервис (около 3 ГБ памяти; модель pix2tex): `install.sh --ocr` или вручную — добавьте `ocr` в `COMPOSE_PROFILES`, задайте `FORMULA_OCR_URL=http://formula-ocr:8502/predict` и `FORMULA_OCR_API_KEY` (случайная строка) в `.env`, затем `docker compose up -d --build`. Рукописи учеников при этом не уходят во внешние сервисы.

### Файлы и хранилище

Картинки и PDF хранятся на диске в томе Docker `uploads`, база — в томе `pgdata`. Вместо диска можно подключить S3-совместимое хранилище (MinIO и т. п.): `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY` в `.env`.

### Windows 10

Запуск на компьютере с Windows для класса в локальной сети — [docs/WINDOWS.md](docs/WINDOWS.md).

## Разработка

Нужны Node.js 22 или новее и PostgreSQL 16. Локально подойдёт `apt install postgresql` или контейнер `postgres:16`.

```bash
# 1. База данных (один раз)
sudo -u postgres psql -c "CREATE USER doska WITH PASSWORD 'doska' CREATEDB;"
sudo -u postgres createdb -O doska doska        # основная
sudo -u postgres createdb -O doska doska_test   # для тестов

# 2. Настройки: скопируйте пример и заполните
cp .env.example .env
#   для разработки:
#   NODE_ENV=development
#   DATABASE_URL=postgresql://doska:doska@localhost:5432/doska?schema=public
#   JWT_ACCESS_SECRET=<openssl rand -base64 48>
#   PUBLIC_ORIGIN=http://localhost:5173,http://localhost:3000
#   COOKIE_SECURE=false
#   SEED_ADMIN_PASSWORD=<пароль с буквой и цифрой, без логина внутри>

# 3. Установка, миграции, первый администратор
npm install
npm run build:shared
npm run db:migrate
npm run db:seed

# 4. Запуск (в двух терминалах)
npm run dev:backend    # API: http://localhost:3000, проверка: /api/health
npm run dev:frontend   # интерфейс: http://localhost:5173 (проксирует /api на бэкенд)

# Проверки
npm run check   # типы + тесты (shared, backend, frontend) + сборка + схема Prisma
npm test
```

Войдите под администратором из `SEED_ADMIN_LOGIN` и `SEED_ADMIN_PASSWORD`. При первом входе система попросит сменить пароль.

Тесты бэкенда используют отдельную БД. Адрес задаётся переменной `TEST_DATABASE_URL`, по умолчанию `postgresql://doska:doska@localhost:5432/doska_test`; миграции применяются к ней автоматически.
