# Модель доски и объектов

Исходный код модели лежит в `packages/shared/src/board/`.

## 1. Yjs-документ доски

На каждую доску приходится один `Y.Doc`, и все страницы хранятся внутри него.

```
Y.Doc
├── meta    : Y.Map<string, Json>
│     schemaVersion: 1, createdAt
├── pages   : Y.Map<pageId, Y.Map<field, Json>>
│     id, title, order, background{kind, step, surface, originX, originY},
│     backgroundLocked, createdBy, createdAt
└── objects : Y.Map<objectId, Y.Map<field, Json>>
      id, type, v, pageId, z, layer, x, y, rotation, scaleX, scaleY,
      locked, hidden, groupId, deps, createdBy, createdAt, updatedBy,
      updatedAt, props
```

Ключевые решения:

1. **Плоская структура, глубина не больше 2.** Все объекты лежат в одной карте `objects`, а не внутри страниц, поэтому любое изменение имеет вид `корень → запись → поле`. Сервер однозначно определяет, какой объект и какое поле затрагивает каждое обновление, и проверяет права точечно. Перенос объекта на другую страницу сводится к изменению одного поля `pageId`. Клиент держит индекс `pageId → Set<objectId>`.
2. **В полях только JSON.** Вложенные `Y.Map`, `Y.Array` и `Y.Text` внутри объектов запрещены. Сервер компенсирует такие изменения как `INVALID_VALUE`.
3. **Поле — единица слияния.** Если два пользователя одновременно меняют разные поля одного объекта (один двигает, другой меняет цвет), сохраняются оба изменения. `props` записывается целиком (last-writer-wins). Одновременная правка свойств одного объекта двумя людьми на уроке бывает редко, а атомарная запись `props` гарантирует, что их набор всегда согласован с zod-схемой модуля.
4. **Недорисованный штрих не пишется в документ.** Пока пользователь рисует, точки идут через awareness (`drawing`), и остальные видят линию в реальном времени. Объект создаётся одной транзакцией при отпускании пера. Так нет потока мелких обновлений, а undo отменяет штрих целиком.
5. **Производные данные не хранятся.** Зависимые построения (перпендикуляр, изображение в линзе, силовые линии) хранят только определение (ссылки на опорные объекты и параметры), а геометрию каждый клиент вычисляет сам. Поэтому движение точки — одна запись, а не каскад записей во все зависимые объекты.

## 2. Базовые поля объекта

| Поле | Тип | Назначение |
|---|---|---|
| `id` | string (nanoid, 21) | совпадает с ключом в `objects`; неизменяемо |
| `type` | string | `"<плагин>.<имя>"`, например `core.stroke`, `math.planimetry.segment`, `physics.optics.lens`; неизменяемо |
| `v` | int ≥ 1 | версия схемы `props` для миграций |
| `pageId` | string | страница |
| `z` | string | порядок отрисовки, дробный индекс (см. ниже) |
| `layer` | `background` \| `content` \| `review` | подложка / содержимое / пометки учителя |
| `x`, `y` | number | мировые координаты начала локальной системы объекта |
| `rotation` | number (рад) | поворот по часовой стрелке |
| `scaleX`, `scaleY` | number | масштаб |
| `locked` | boolean | блокировка учителем |
| `hidden` | boolean | скрыт (например, ответ, который учитель покажет позже) |
| `groupId` | string \| null | группа (`core.group`) |
| `deps` | string[] | объекты, от которых зависит этот (динамическая геометрия) |
| `createdBy`, `createdAt` | uuid, мс | автор и время создания; проверяются сервером; неизменяемы |
| `updatedBy`, `updatedAt` | uuid, мс | последнее изменение |
| `props` | JSON | свойства типа; схему задаёт модуль объекта |

Трансформация применяется в порядке «масштаб → поворот → перенос» (`transformToMatrix`).
Модуль объекта описывает геометрию в **локальных** координатах, а ядро применяет трансформацию само. Поэтому выделение, перемещение, поворот, масштаб и группировка работают для любого типа без участия плагина.
Плагин может запретить поворот или масштаб (`transform.rotatable`, `transform.resize`). Например, точка динамической геометрии двигается только целиком, а её координаты лежат в `x/y`.

### Слои и порядок

Отрисовка идёт по слоям `background` → `content` → `review`, а внутри слоя — по `(z, id)`.
`z` — дробный индекс (`board/fractional-index.ts`): чтобы поставить объект между A и B, генерируется ключ строго между `A.z` и `B.z`.
Команды «На передний план», «Вперёд», «Назад» и «На задний план» меняют только `z` перемещаемых объектов.
Если при одновременной вставке ключи совпали, порядок определяет `id` (`compareOrder`).

### Группы

Группа — объект типа `core.group` без собственной геометрии. Его `props.name` необязателен, а дети ссылаются на него через `groupId`.
Группы могут быть вложенными. Клик выделяет группу верхнего уровня, двойной клик входит внутрь.
Трансформация группы пересчитывает `x/y/rotation/scale` детей в одной транзакции.
Разгруппировка обнуляет `groupId` у детей и удаляет объект группы.

### Блокировка

`locked: true` ставит и снимает только учитель.
Блокировка всей подложки страницы задаётся флагом `pages[p].backgroundLocked`: объекты слоя `background` и параметры фона страницы становятся доступны только учителю.
Типичный сценарий — «условие задачи нельзя сдвинуть или стереть»: учитель вставляет PDF или текст условия как `background` и включает блокировку.

### Авторство

`createdBy` и `createdAt` сервер проверяет при создании. Если автор не совпадает с пользователем соединения, объект компенсируется.
При наведении клиент показывает «Нарисовал(а): Иванов И., 10:42». Ученикам подсказка показывается, если включена настройка `showAuthorsToStudents`.
По `createdBy` работают «Очистить следы учеников» и «Удалить объекты ученика…».

### Динамическая геометрия и зависимости

Объекты динамической геометрии ссылаются на опорные объекты через `deps`, а параметры построения хранят в `props`.
Например, перпендикуляр выглядит так: `{ type: 'math.planimetry.perpendicular', deps: [pointId, lineId], props: { through: pointId, to: lineId } }`.
Ядро поддерживает граф зависимостей:
- при изменении объекта зависимые пересчитываются в порядке топологической сортировки; это локальные вычисления без записи в документ;
- при удалении опорного объекта появляется предупреждение «От этого объекта зависят N построений: удалить вместе с ними / отменить»;
- если ссылка висячая (опорный объект удалён другим пользователем), объект рисуется серым пунктиром с пометкой «нет опоры» и может быть восстановлен через undo автора;
- циклы запрещены: инструменты ссылаются только на уже существующие объекты, а пересчёт обходит граф с защитой от цикла в испорченном документе.

Реализация (6.1a): `BoardModel` ведёт карту «опора → построения», пересчитывает габариты построений после каждой транзакции (`refreshOrder`), отдаёт `dependentsOf`, `movableSet`, `hasDependents`. Объект с `derived: true` двигается своими свободными опорами; удаление опоры с построениями подтверждается («Удалить вместе с ними»), ластик удаляет их сразу; копирование построения захватывает его опоры.

### Цвета

В `props` цвет — это либо семантический токен (`ink`, `accent-1` … `accent-8`, `muted`), либо `#RRGGBB`.
Токены переводятся в цвет текущей темы через `RenderContext.resolveColor`, поэтому один и тот же чертёж читается на белом, тёмном и «меловом» фоне.
Физические обозначения следуют общей палитре: силы, скорости, поля E и B получают фиксированные токены (этап 7).

## 3. Страницы

Каждая запись в `pages` — это `PageRecord` (`board/doc-layout.ts`). Порядок вкладок задаёт поле `order`, тоже дробный индекс.
Удаление страницы удаляет её запись и все объекты с этим `pageId` в одной транзакции.
Фоны: `blank`, `grid`, `ruled`, `dots`, `millimeter`, `polar`, `isometric`.
`surface: 'chalk'` включает «меловую доску» (тёмно-зелёный фон) для конкретной страницы. Светлую и тёмную тему пользователь выбирает для себя.
PDF вставляется постранично: каждая выбранная страница PDF становится отдельной страницей доски, а сама страница PDF — её фоном (`background.pdf`: файл, номер страницы, размер в мировых единицах, левый верхний угол в начале координат). Рисует её браузер (pdf.js). Учитель может сразу закрепить фон (`backgroundLocked`).

## 4. Каталог типов объектов

Ниже перечислены типы и этапы, на которых они появятся. Каталог дополняется плагинами, ядро от него не зависит.

| Плагин (этап) | Типы |
|---|---|
| `core` (3, 5) | `core.group`, `core.stroke` (перо/маркер, `points: [x,y,p,…]` в локальных координатах, `width` — мировые единицы, `pressure`, `opacity`, `closed`, `kind: pen \| marker`; до 5000 точек, длиннее — несколько объектов), `core.shape` (прямоугольник, эллипс, линия, стрелка, треугольник, многоугольник), `core.text` (`doc` — документ ProseMirror по схеме `text/schema.ts` с формулами `mathInline`, `w` — ширина переноса, `h` — измеренная высота, `fill` — подложка; растяжение рамкой меняет ширину, а не масштаб), `core.formula` (`latex`, `size` — кегль, `color`; растяжение меняет кегль), `core.solution` (`title`, `steps: [{latex, note}]` до 60, `w` — ширина, `size`, `check` — показывать отметки проверки переходов; высота по содержимому), `core.image` (`assetId`, размер на доске `w`×`h`, исходный размер, обрезка `crop` в пикселях файла), `core.calc` (результат калькулятора: `expr` — запись в калькуляторе, `latex` — «запись = результат», `size`, `color`; рисуется как формула) |
| `math.planimetry` (6.1) | **6.1a:** `math.planimetry.point` (`x`, `y` — положение; `label`, `color`, `size` — радиус на экране, `auto` — создана вместе с построением) и фигуры на точках с `derived: true` — `segment`, `ray`, `line`, `vector` (2 точки), `polyline` (≥2), `polygon` (≥3), `regular-polygon` (2 точки стороны + `n`), `circle` (центр, точка окружности), `arc`, `sector`, `circle-segment` (центр, начало, конец — против часовой стрелки), `ellipse` (центр, конец полуоси, точка второй полуоси). Точки — в `deps` по порядку; `props`: `color`, `width` (пт на экране), `dash`, `label`, `fill`, `n`, `fb` (координаты опор при создании — рисуются серым пунктиром «нет опоры», если опору удалили). Далее: точка, отрезок, луч, прямая, вектор, ломаная, многоугольник, правильный n-угольник, окружность, дуга, сектор, сегмент, эллипс, построения (перпендикуляр, параллель, биссектриса, касательные, замечательные линии/точки, вписанная/описанная окружность), преобразования, отметки углов и равенства, инструменты (линейка, транспортир, циркуль) |
| `math.analysis` (6.2) | система координат, функция, параметрическая/полярная/неявная кривая, неравенство, касательная/секущая, площадь, суммы Римана, ε-δ, Тейлор, Фурье, числовая прямая, тригонометрическая окружность, слайдер, таблица значений |
| `math.analytic`, `math.linalg` (6.3) | прямые/плоскости по уравнению, кривые 2-го порядка, векторы с координатами, матрица, шаги метода Гаусса, линейное преобразование |
| `math.stereo` (6.4) | 3D-сцена (`math.stereo.scene` — тела, сечения, прямые и плоскости внутри `props`), плоский чертёж из 3D |
| `math.multivar`, `math.ode`, `math.complex`, `math.probability`, `math.discrete` (6.5) | поверхности, линии уровня, векторные поля, поле направлений, фазовый портрет, комплексная плоскость, диаграммы, распределения, деревья, графы, таблицы истинности, логические схемы |
| `physics.*` (7.1–7.8) | вектор величины, тела, опоры, пружины, блоки, наклонная плоскость, заряды, поля, элементы цепей, магниты, линзы, зеркала, диаграммы и т. д. |

У 3D-сцены вся внутренняя модель (тела, точки, сечения) хранится в `props` одного объекта, и его размер не превышает 512 КБ.
Сцена является единым объектом доски, а её содержимое редактируется во встроенном 3D-редакторе. Это сохраняет глубину документа равной 2 и упрощает проверку прав.

## 5. Неизвестные типы и миграции

- Если клиент не знает тип (раздел отключён или клиент старой версии), объект рисуется заглушкой «Неизвестный объект (тип)» по сохранённым габаритам `props.__bounds`, если они есть. Данные при этом **не меняются**: ядро никогда не перезаписывает чужие поля.
- Если `obj.v < module.version`, ядро вызывает `module.migrate(props, v)` при первом **изменении** объекта и записывает результат вместе с новым `v`. Только чтение объект не мигрирует, чтобы клиенты разных версий не устраивали «войну записей».
- Если `props` не проходит `propsSchema`, объект рисуется заглушкой «Повреждённый объект» и его можно удалить.
- Структура документа версионируется через `meta.schemaVersion` (`DOC_SCHEMA_VERSION`). Глобальные миграции выполняет сервер при загрузке документа.

## 6. Сериализация вне Yjs

Шаблоны, копирование между досками, буфер обмена и экспорт JSON используют формат `SerializedBoardObject` (`boardObjectSchema`).
При вставке или копировании выдаются новые `id`, ссылки в `deps`, `groupId` и `props` переписываются по таблице соответствия, `createdBy` и `createdAt` получают значения текущего пользователя, а `z` генерируется заново.
Модуль может переопределить `serialize`/`deserialize`, например чтобы вынести бинарные данные картинки в `assetId`.
